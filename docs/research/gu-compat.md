# MHGU (영문판) 모드·플러그인을 덥크에서 — 설계 (초안, 2026-11-12)

0.7부터 가장 많이 요청된 기능. 목표: 영문판(MHGU 1.4.0)용 **Forge 플러그인**과 **데이터 모드**를 일어판 덥크
(1.5.1)에서 쓰게 하기. 캡콤 데이터는 어떤 것도 배포하지 않는다(변환은 사용자 PC에서, 사용자의 덥크 파일과 사용자가
받은 모드로).

## 0. 전제

- Forge 플러그인은 **AArch32 .nro**(게스트 코드)로, 모드의 romfs `nativeNX/plugins/`에 들어 있고 포팅이 게스트 안에서
  실행한다(runtime/forge.c). 플러그인은 게임 메모리를 **게스트 주소로 직접** 읽고 쓰며, `forge_hook_create(target, …)`로
  게임 함수에 훅을 건다. 그래서 영문판에서만 도는 이유는 (1) 덥크에서 Forge가 꺼져 있고(addr.h FORGE_PORTED: 찾은 주소
  1/6), (2) 플러그인 안의 **영문판 주소 상수**가 덥크에서는 다른 곳을 가리키기 때문.
- 두 판의 코드는 구간별로 일정하게 밀려 있다(예: 마을 코드 GU − 0xb160, 소리 코드 GU − 0x51d8, 몬스터 갱신
  GU − 0x12c4). 구조체 안의 위치는 지금까지 본 것은 같다(몬스터 +0x1428, 시스템 +0x68 등).
- addr.h에 이미 GU ↔ 덥크 주소 쌍이 수십 개 있다: 변환표의 씨앗.

## 1. Forge 켜기 (선행)

> **2026-11-12: 주소 5개 모두 찾음** (addr.h의 A_FORGE_OFF_*). sApp::run 0xd7b344, cSystem 생성자·소멸자 0xa7c22c / 0xa7c268,
> sSavedata mount 0xa6d7bc, job safe 0x234241c. 코드 구간은 GU − 0xb5e4~0xb5e8, 전역 데이터는 GU + 0x22000.
> 남은 것: 덥크용 플러그인 하나로 실제 동작 확인.

- 남은 주소 5개를 덥크에서 찾는다: sApp::run(GU 0xb8692c), cSystem 생성자·소멸자(0x887810 / 0x88784c), sSavedata
  mount(0x878da0), job safe(0x212041c). 오늘 fastload처럼 GU 주변 코드 모양과 구간 간격으로 찾고 코드로 확인.
- FORGE_PORTED가 켜지면 **덥크용으로 만든 플러그인**은 그대로 돈다(아직 거의 없지만 기반).

## 2. 플러그인 주소 변환 (GU 플러그인 → 덥크)

> **2026-11-12: 방식 변경, 첫 구현** (runtime/gucompat.c, game/gu2xx.h). 플러그인은 주소 상수가 아니라
> `forge_mem_getMainTextAddr() + 오프셋`으로 게임에 접근한다(Damage Numbers r42). 그래서 상수를 고쳐 쓰는 대신
> **영문판 주소 그대로 보이는 영역**(0xA0000000)을 만들어 그 시작 주소를 돌려준다: 표에 있는 함수는 그 영역의 영문판
> 자리에 덥크 코드를(바깥 호출은 영문판 대상 주소로 다시 써서) 놓고, 그 영역으로의 호출·훅·패치는 덥크 주소로 바꾼다.
> 플러그인 파일은 건드리지 않는다. 파일 이름에 "mhxx"가 있으면 덥크용으로 보고 변환하지 않는다.
> Damage Numbers는 자기가 쓰는 15곳의 코드 64바이트를 검사한다: 그 검사 조각으로 덥크 위치 14곳 + 호출 대상을 찾았고
> (표 26개 함수), 오프라인 검증에서 15곳 모두 통과. 게임에서의 동작 확인은 아직.
> 표를 넓히는 길: 영문판 실행 파일(1.4.0)이 있으면 함수 전체를 자동 대응.

플러그인을 불러올 때(forge.c, .nro를 읽은 뒤 심볼 해석 전) **영문판 게임 주소 상수를 덥크 주소로 고쳐 쓴다.**

1. **변환표** `gu2xx`: 구간 표(GU 시작, 끝, 덥크까지의 차이) + 개별 예외(함수 하나 단위).
   - 씨앗: addr.h의 GU/덥크 쌍. 그 사이 구간은 양 끝 쌍의 차이가 같으면 같은 차이로, 다르면 함수 단위로 맞춰 확인.
   - 표는 숫자뿐이라 배포해도 캡콤 데이터가 아님. `tools/gu2xx.txt` 같은 글 파일로, 플러그인 하나 맞출 때마다 늘림.
2. **상수 찾기**: 플러그인 코드의 literal pool 워드, `movw/movt` 쌍에서 값이 게임 범위(코드 0x200000~0x1400000, 전역
   데이터 0x2000000~0x2600000 부근)에 드는 것. 플러그인 자신의 재배치(.nro의 relocation) 대상은 건너뜀.
3. **고쳐 쓰기**: 표에 있는 주소만. 표에 없는 게임 주소가 하나라도 있으면 그 플러그인은 **켜지 않고** 어떤 주소가
   빠졌는지 로그와 F1에 보여 줌(엉뚱한 곳을 쓰다 세이브를 망치는 것보다 안전).
4. **훅 대상**: forge_hook_create / forge_patch_create로 들어오는 주소도 같은 표로 한 번 더 확인(상수 찾기가 놓친 것).
5. **구조체 차이**: 플러그인별 예외가 필요하면 "이 플러그인은 몬스터 +X를 +Y로" 같은 덧붙임 표. 처음엔 없다고 가정하고,
   어긋나면 추가.

판별: 플러그인이 영문판용인지는 .nro의 이름·메타데이터나, 상수 중 영문판 범위에만 맞는 주소가 있는지로. 모르면
그대로 불러 보고(덥크용일 수도) 문제 시 변환.

첫 목표: **데미지 표시** 플러그인 하나를 끝까지(F1에 "변환됨" 표시, 실제 데미지 숫자 확인).

> **2026-11-12: Damage Numbers r42가 덥크에서 동작 (실기 확인).** 필요했던 것: 게임 번호를 영문판으로 답하기,
> 트램펄린을 플러그인이 아는 모양으로, 영문판 주소로 돌아오는 점프를 같은 실행 안에서 처리, 데이터 주소 대응표
> (GU2XX_GLOBAL, 30642개)와 플러그인의 movw/movt 상수 고쳐 쓰기. 전체 표는 영문판 1.4.0 실행 파일로
> tools/gu2xx.py가 만든다(코드 97%). 다음: 다른 플러그인으로 넓히기(FF14-style Damage Text 등).

## 3. 데이터 모드 변환

런처의 모드 설치(modinstall.cpp)에서 GU 모드로 보이면 "덥크용으로 변환해서 설치할까요?" → 변환본을 mods/에 따로 만든다
(원본 모드 파일은 그대로).

arc 항목(MT Framework 리소스 종류 해시)별로:

| 종류 | 처리 |
|---|---|
| 텍스처, 모델, 재질, 이펙트 등 외형 | 덥크 게임 파일의 같은 arc·같은 경로·같은 종류가 있으면 그대로 넣음(arc merge가 항목 단위로 합침) |
| 텍스트(GMD) | 기본 제외(한글패치를 영어로 덮음). 원하면 켜는 선택지 |
| 데이터 표(무기·방어구·아이템·스킬·퀘스트 등) | 표 종류별 변환기: 레코드를 ID로 맞춰, 덥크에 있는 ID만 덥크 표에 덮어씀. 레코드 크기가 다르면 그 표는 제외하고 알림 |
| 덥크에 없는 경로·종류 | 제외 |

- 데이터 표의 한계: 영문판 원본 표가 없으니 모드가 **바꾼** 칸만 골라낼 수 없다 → 모드에 들어 있는 레코드를 통째로
  덮어씀. 공통 레코드의 원래 값은 GU와 덥크가 거의 같다고 보고, 다른 게 확인되면 표별로 칸 단위 처리를 추가.
- 표 형식은 **요청 많은 것부터** 하나씩(무기 수치, 방어구, 아이템 순일 듯).
- 끝나면 요약: "외형 42개 적용 · 텍스트 3개 제외 · 무기 표 변환(ID 120개 중 118개) · 2개 경로 없음".

## 4. 순서

1. Forge 주소 5개 → 덥크용 Forge 동작 확인
2. 데미지 표시 플러그인으로 변환표·상수 고쳐 쓰기 끝까지
3. 외형 모드 걸러 넣기(arc 항목 필터) — 가장 싸고 효과 큼
4. 데이터 표: 요청 많은 종류부터
5. 변환표를 넓히며 다른 플러그인

준비물(형): 원하는 모드·플러그인 목록(디시·구글 폼), 샘플 2~3개를 PC의 `F:\MHXX_port\gu_mods\`에(분석만, 업로드 없음).

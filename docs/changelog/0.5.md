# MHXX Recomp 0.5

0.4 이후 추가된 것 (2026-11-08). 런처, 종료 흐름, 메뉴 테마. 게임은 `make`, 런처는 `sh tools/launcher/build.sh`로 빌드.

## 런처 (`mhxx-launcher.exe`) — 새로 추가

| 기능 | 테스트 | 설명 |
|---|---|---|
| **런처** | 확인됨 | 게임 옆의 별도 실행 파일. 재시작이 필요한 설정(화면, 그래픽 일부, 모드)을 게임을 켜기 전에 바꿈. F1 메뉴의 같은 설정은 그대로 둠 |
| **게임 시작** | 확인됨 | 설정을 저장하고 게임을 실행한 뒤 런처는 닫힘. 컨트롤러 + 버튼으로도 시작 |
| **바탕화면 바로가기** | 확인됨 | 처음 실행할 때 "바탕화면에 런처 바로가기를 만들까요?". 이름은 직접 입력(기본 `MHXX Recomp`). 아니요를 누르면 만들지 않고 바로 런처로. 한 번 답하면 다시 묻지 않음(`launcher.ini`) |
| **더블크로스 디자인** | 확인됨 | 배경과 로고는 **본인 게임 파일의 타이틀 화면**(`title.arc`, 한글패치가 있으면 그쪽)에서 실행할 때 읽어 옴. 런처 안에는 게임 그림이 들어 있지 않음. 남색 패널, 금색 테두리, 호박색 버튼 |
| **상태 표시** | 확인됨 | 게임 파일 확인 여부, 게임 실행 중 여부, 설치된 모드 수, 텍스처 팩 수 |
| **저장 안 한 채 종료** | 확인됨 | 설정을 바꾸고 종료(버튼 또는 창 X)하면 "저장하지 않은 변경이 있습니다. 저장할까요?" → 저장 후 종료 / 저장하지 않고 종료 / 취소 |
| **게임 실행 중 잠금** | 확인됨 | 게임이 켜져 있으면 "게임 실행 중"을 띄우고 시작과 설정 변경을 막음(게임이 설정을 저장하면서 덮어쓰기 때문). 게임을 끄면 1초 안에 풀림 |

## F1 메뉴

| 기능 | 테스트 | 설명 |
|---|---|---|
| **나가기 선택** | 확인됨 | 메뉴 옵션 탭의 "런처로 나가기" / "바탕화면으로 나가기", 또는 창 X → "어디로 나가시겠습니까? 저장하지 않았다면 저장 후에 나가주시기 바랍니다" → 런처로 나가기 / 바탕화면으로 나가기 / 취소. 처음 커서는 취소. 런처가 없는 폴더에서는 예전처럼 "정말 나가시겠습니까?" 네 / 아니오 |
| **더블 크로스 테마** | 확인됨 | 메뉴 옵션 → 메뉴 테마 → 더블 크로스. 런처와 같은 남색 패널, 금색 이중 테두리와 모서리 마름모, 고른 줄은 호박색. 채팅 입력창도 같은 색. 골드 / 블루 / 헌터 테마는 그대로 |

## 고친 것

| 문제 | 원인 | 해결 |
|---|---|---|
| 게임을 켜면 흰 창이 잠깐 보임 (처음부터 있던 것) | 창을 만들자마자 보여 줬는데, 게임이 첫 화면을 그리기 전엔 아무것도 칠해지지 않아 윈도우가 흰색으로 표시. 창 크기에서 전체 화면으로 바뀌는 과정도 보였음 | 창을 숨긴 채 만들고, 전체 화면으로 바꾸고, 검게 칠한 뒤 보여 줌 (확인됨) |
| 런처의 시작·종료 버튼이 눌리지 않음 | 오른쪽 설정 메뉴가 매 프레임 자기 창으로 포커스를 가져가서 왼쪽 버튼을 누르는 도중 끊김. 게임 안에서는 메뉴 창이 하나뿐이라 드러나지 않았음 | 런처에서는 다른 창의 버튼을 누르는 동안 포커스를 가져가지 않음 (확인됨) |

## 시도했다 되돌린 것
- **텍스처 팩 압축(DDS, BC7)**: 업스케일 텍스처를 압축해 메모리와 용량을 줄이려 했으나 방어구 일부가 검게 나와 되돌림. 압축 파일과 스크립트, 코드 패치는 작성자 바탕화면 `MHXX_DDS압축_백업`에 보관. 맵(stage)까지 키우려면 다시 해야 함.

## 앞으로: 남은 업스케일링 (다음 버전 이후)

0.4에서 방어구·무기·오토모·몬스터 텍스처를 키웠습니다. 완성도를 위해 나머지도 같은 방식으로 키울 계획입니다.

| 대상 | 방법 | 상태 / 걸리는 점 |
|---|---|---|
| **오프닝·이벤트 영상** (`romfs\nativeNX\movie\movie00~09.mp4`, 10개, 약 1.4GB) | 프레임을 풀어 Real-ESRGAN 영상용 모델(`realesr-animevideov3`)로 키운 뒤 다시 mp4로. 모드 폴더에 같은 경로로 넣으면 원본 대신 재생됨(이미 지원) | **뒤로 미룸.** 게임이 더 큰 영상을 그대로 그리는지 짧은 영상으로 먼저 확인 필요. 전체 변환은 그래픽카드로 몇 시간 단위 |
| 맵(stage) 텍스처 | 텍스처 팩과 같음 | 개수와 크기가 커서 압축(BC7)이 먼저 해결돼야 함 |
| 소형 몬스터, 이펙트, 아이콘·UI | 텍스처 팩과 같음 (UI는 한글패치 텍스처 기준) | 분류만 골라 `upscale.py`로 실행하면 됨 |

### 모델링은 하지 않음
몬스터, 장비, 맵 모델을 라이즈급으로 다시 만드는 일은 AI 변환이 안 되고 사람이 수천 개를 직접 모델링해야 하며, 원래 뼈대·애니메이션·판정에 맞춰야 합니다. 다른 게임의 모델을 옮겨 오는 것은 배포할 수 없습니다. 대신 모델을 바꾸지 않고 화면을 더 깔끔하게 하는 방법(먼 거리 디테일 유지, 그림자 해상도, 안티에일리어싱, SSAO)을 포팅 쪽에서 검토할 수 있습니다.

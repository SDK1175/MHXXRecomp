# MHXX Recomp 0.6

0.5 이후 추가된 것 (2026-11-08). 런처의 게임 파일 설치, 배포판에 런처 포함. 게임은 `make`, 런처는 `sh tools/launcher/build.sh`, 배포판은 그 다음 `make dist VERSION=0.6 ANDROID_DIST=`.

## 런처: 게임 파일 설치 — 새로 추가

| 기능 | 테스트 | 설명 |
|---|---|---|
| **설치 화면** | 테스트 파일로 확인 (실제 게임 파일은 확인 전) | 게임 파일이 없으면 런처 메인 전에 나옴. 메인 화면 왼쪽의 **게임 파일 설치** 버튼으로 언제든 다시 열 수 있음 |
| **고를 파일** | 테스트 파일로 확인 | 게임 원본(1.0.0, NSP 또는 XCI), 업데이트(1.5.1, NSP), 키 파일(prod.keys), 한글패치(zip, 선택)를 탐색기로 고름 |
| **자동 설치** | 테스트 파일로 확인 | 런처가 복호화하고 업데이트를 합쳐 `data\exefs`, `data\romfs`에 넣고, 한글패치는 `mods\<zip 이름>`에 풂. 진행 막대, 지금 쓰는 파일, 용량 표시 |
| **키 자동 찾기** | 테스트 파일로 확인 | Eden, yuzu 계열(suyu, citron, sudachi, torzu), Ryujinx 폴더에 prod.keys가 있으면 미리 채워 둠 |
| **확인과 오류** | 테스트 파일로 확인 | 업데이트가 1.5.1인지 exefs/main의 빌드 ID(`9D4C86E6EF74504A`)로 확인. 키가 안 맞음, 원본과 업데이트를 바꿔 고름, 다른 게임의 업데이트, NSZ/XCZ, 비밀번호 걸린 zip, 7z/rar는 이유를 알려 줌. 자세한 기록은 런처 폴더의 `install.log` |
| **안전한 교체** | 테스트 파일로 확인 | 새 파일을 `exefs.new`, `romfs.new`에 다 쓴 뒤에만 기존 파일과 바꿈. 바꾸다 실패하면 원래 파일로 되돌림. 설치 중 창을 닫으면 멈추고 쓰던 파일은 지움 |

### 동작 (`tools/launcher/nxinstall.cpp`)
- NSP(PFS0)와 XCI(HFS0의 secure 파티션, 앞에 키 영역 0x1000이 붙은 덤프 포함)를 읽음.
- NCA 헤더는 header_key로 AES-XTS 복호화(섹터 번호를 빅엔디언으로 쓰는 닌텐도 방식). 섹션은 키 영역(key_area_key_application_세대) 또는 티켓의 타이틀 키(titlekek_세대)로 AES-CTR.
- 업데이트의 RomFS는 패치(BKTR): Indirect 표로 원본/업데이트 데이터를 이어 붙이고, AesCtrEx 표의 구간별 카운터로 업데이트 데이터를 복호화. ExeFS는 업데이트 것을 씀.
- 게임 카드(XCI)에 업데이트가 같이 들어 있어도 원본 프로그램을 골라 씀.
- prod.keys에 master key와 source만 있어도 header_key, key_area_key, titlekek를 계산함.
- AES는 CPU의 AES 명령(AES-NI)을 씀(300MB에 1초 미만). 없는 CPU는 일반 계산(약 60MB/s).
- 한글패치 zip: 무압축/deflate, 한국어 윈도우에서 만든 zip의 한글 파일 이름(CP949) 처리. 4GB 넘는 zip(zip64)은 못 읽음.
- 게임 파일과 키는 런처 안에 없고 전부 본인 파일에서 읽음.

### 테스트
공개된 형식(switchbrew, hactool)대로 만든 가짜 NSP/XCI(별도 AES 라이브러리로 암호화)로 확인:
- NSP 원본, XCI 원본(키 영역 포함) 모두 업데이트를 합친 결과가 정답과 같음
- master key만 있는 prod.keys로 설치됨
- AES 명령 없이 계산해도 결과가 같음
- 잘못된 키, 원본·업데이트 바꿔 고르기, 업데이트 대신 원본 두 번 고르기 → 오류 메시지
- 설치 중 창 닫기 → 쓰던 파일 지워짐

**실제 MHXX 파일로는 아직 확인 전.**

## 배포판
- `make dist`가 만드는 zip에 `mhxx-launcher.exe`가 들어감(`tools/dist.py`). 런처는 `make`가 아니라 `sh tools/launcher/build.sh`로 빌드하므로 그 다음에 `make dist`. 런처를 빌드하지 않았으면 "mhxx-launcher.exe is missing (sh tools/launcher/build.sh first)"로 멈춤.
- 런처는 zip에 이미 있는 `SDL3.dll`을 같이 씀.

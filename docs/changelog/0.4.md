# MHXX Recomp 0.4

0.3 이후 추가된 것 (2026-11-07 ~ 11-08). 그래픽, 특히 텍스처. 런타임만 바뀌었으므로 `make`로 빌드.

## 그래픽

| 기능 | 테스트 | 설명 |
|---|---|---|
| **이방성 필터링** | 빌드 확인 | F1 → 그래픽 및 오디오. 게임 기본 / 2x / 4x / 8x / 16x, 기본 16x. 비스듬히 보이는 바닥·벽 텍스처를 선명하게. 그림자·렌더 타깃·UI 샘플러에는 적용 안 함 (`nvn/vulkan/textures.c`) |
| **텍스처 덤프** | 확인됨 (439개) | F1 → 그래픽 및 오디오 → 텍스처 덤프. 게임에 나온 텍스처를 `textures/dump/<키>.png`로 한 번씩 저장, `index.txt`에 크기·종류. 별도 스레드에서 처리 (`nvn/vulkan/texpack.c`) |
| **텍스처 교체 (텍스처 팩)** | 확인됨 | `textures/load/<키>.png`가 있으면 원본 대신 그 그림을 씀. 크기는 자유(비율만 같게), 밉맵은 GPU가 생성. 게임이 텍스처 내용을 바꾸면 원본으로 돌아감 |

키: 텍스처 원본 크기 레벨(배치를 풀어 놓은 블록 데이터)과 크기, NVN 형식의 해시. 실행할 때마다, 사람마다 같음.

## 도구

### `mhxx-texextract` (텍스처 뽑기)
- 게임 파일(romfs)의 `.arc`를 직접 열어 모든 2D 텍스처를 덤프와 같은 이름 규칙으로 PNG 저장. 모드(한글패치)의 `.arc`가 있으면 그쪽을 읽음.
- `index.txt`에 크기, 종류, `.arc`, 게임 안 텍스처 이름까지 기록.
- 결과: 텍스처 50,970개 중 고유 22,036개 저장. 모르는 형식 24개(0x15, 0x1e, 0x20, 0x2a), 큐브맵 등 141개 제외.
- 검증: 게임 안 덤프 439개 중 424개가 이름 일치(나머지는 한글패치 없이 뽑은 UI).
- TEX 형식: 0x07 RGBA8, 0x13 BC1, 0x17 BC3, 0x19 BC4, 0x1f BC5. 헤더 +0x10 데이터 크기, +0x14 레벨마다 오프셋, 그 뒤에 데이터.
- 빌드: `sh tools/texextract/build.sh` (또는 `make texextract`)

### `tools/texpack/upscale.py` (업스케일)
- 뽑은 텍스처에서 분류(player, weapon, otomo, enemy, stage …)를 골라 업스케일하고 `textures/load`에 바로 저장.
- 컬러: realesrgan-ncnn-vulkan의 `realesrgan-x4plus-anime` (그래픽카드). 투명도는 따로 확대해서 다시 합침.
- 노멀맵·마스크: Lanczos 확대.
- 이미 만든 건 건너뜀(이어하기 가능).
- 모델 비교: x4plus, anime_6B, general-x4v3 중 anime_6B가 손그림 장비 텍스처의 선과 무늬를 가장 잘 살림.

## 알게 된 것
- 덥크 장비 텍스처는 거의 전부 128x128(3DS 시절 그대로). 흐릿해 보이는 가장 큰 원인.
- 몬스터·맵은 대부분 이미 1024x1024.
- 셰이더 캐시는 플레이하면서 쌓임(작성자 PC 6,311개). 처음 하는 PC에서만 첫 등장 끊김이 있을 수 있음.

## 아직 안 된 것

- 모르는 TEX 형식 4종 (24개)
- 고프레임 연타 판정, 몬스터 표적 고르기
- 체력 배율, 집회소에서 마을 퀘스트, 소형 몬스터 동기화, 긴급 퀘스트 공유, 디스코드, 보너스 콘텐츠
- 멀티 테스트
